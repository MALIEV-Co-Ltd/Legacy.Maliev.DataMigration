# Current Auth local session archive

The operation removes only a freshly reviewed set of local `public.refresh_sessions` after retaining independently recoverable archives. Production is a read-only comparison fleet for this operation. It is not a generic deletion, schema repair, source23 refresh, application restore or deployment command.

All eleven session fields participate in typed comparison and canonical CAS, including null/empty distinctions, literal Unicode and UTC microsecond timestamps. The bounded reviewed set may contain any positive supported count; historical observations of two local rows are not current authority. Unsupported triggers, rules, row policies or foreign-key dependencies reject before deletion.

Production sessions must independently be empty. Application comparison checks Google nonces and identity action tokens. Each target preserves its own EF history, complete raw catalog multiplicity, private journals, other rows and physical sequence tuples; histories are never copied between targets merely to equalize their hashes.

## Guarded effects

1. Verify fresh review and independent authorization, accepted source/owner/custody, both actual targets, exact inventories and installed maintenance exclusion.
2. Reserve a create-new operation. Recapture both complete fleets and lock the four local Auth tables in a Serializable transaction.
3. Reproduce the exact locked preimage. Retain protected recovery material and two independently randomized encrypted copies on verified independent failure domains. Held readback and real decryption must reproduce the original bytes.
4. Recheck authority and policy. Execute only parameterized deletion of the exact reviewed identifiers, returning all eleven fields and comparing the complete returned set.
5. Prove only the supported local session change occurred. Revalidate both recovery copies and durably acknowledge signed Prepared before COMMIT.
6. Retire the writer and independently read back the committed local state and both complete fleets. Publish terminal evidence only after exact preservation, application comparison and recovery checks.

Failure, drift, expiry, reservation collision or uncertain acknowledgement causes sticky Stop. No automatic retry or historical adoption follows. Never truncate, recreate, replace a persistent database, erase journals or discard local-only data to obtain equality.
